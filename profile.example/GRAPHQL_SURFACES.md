# GRAPHQL SURFACES — find the query or mutation before you write one

**The developer never writes a new resolver, mutation, or FE document before proving the existing one does not
exist.** Duplicating a query that already ships is the most common defect in a workspace whose surface is spread over
several services and frontends.

Every path is relative to the workspace root.

## Backend — one endpoint per service

| Service | Namespace | Schema | Endpoint |
|---|---|---|---|
| `orders` | `Orders::` | `monorepo/gems/orders/app/graphql/orders/schema.rb` | `:3000/orders/graphql` |
| `catalog` | `Catalog::` | `monorepo/gems/catalog/app/graphql/catalog/schema.rb` | `:3000/catalog/graphql` |

Each service lays its GraphQL out identically:

```
app/graphql/<service>/
  schema.rb            the schema root
  query_type.rb        every query field — READ THIS FIRST
  mutation_type.rb     every mutation field — READ THIS FIRST
  resolvers/           one class per query field
  mutations/           one class per mutation, grouped by domain
  types/               object types
  sources/             GraphQL::Dataloader sources (N+1 defence)
```

`query_type.rb` and `mutation_type.rb` are the **authoritative index**. A field that is not registered there does not
exist, however many resolver files you find.

### The inventory commands

With the brain set up (`ai-brain/docs/AI_BRAIN.md`), ask it first; the greps below are the path without it.

```
ai-brain/bin/ai-brain surface <domain words>   # fields, operations, routes, topics, tables, by name
ai-brain/bin/ai-brain impact <Type.field>      # who selects it, the resolver, the specs, the notes
```

```
grep -nE '^\s*(field|def)\s' monorepo/gems/orders/app/graphql/orders/query_type.rb
grep -nE '^\s*(field|def)\s' monorepo/gems/orders/app/graphql/orders/mutation_type.rb
grep -rn "<domain word>" monorepo/gems/*/app web-app/src admin-app/src
```

## Frontend — the micro-frontends

```
web-app/
  schema.graphql           dumped backend SDL — the FE's view of the backend
  src/graphql/queries/     query documents
  src/graphql/mutations/   mutation documents
  src/gql/                 GENERATED by codegen — never hand-edit
  src/hooks/               use<Feature> hooks wrapping the documents
  src/pages/, src/components/, src/helpers/
```

**`schema.graphql` is a snapshot.** A field in the backend but not in `schema.graphql` is invisible to the FE until
the schema is dumped and codegen runs (`ai-brain/profile/REPOS.md`, "Codegen").

## The verdict every survey must produce

For each thing the ticket needs, exactly one of:

- **reuse as-is** — it exists; name `file:line` and the operation name.
- **extend** — it exists but is missing a field, filter or argument; name what is added.
- **write new** — nothing covers it; say what you searched to be sure.

### The verdicts decide the stack

- **Every backend need is reuse as-is → the ticket is `FE`.**
- **Any backend need is extend or write new → `FE+BE`** (or `BE`), and the backend work is scoped to exactly that.
- **The field exists in the backend but not in the frontend's `schema.graphql` → still `FE`**, plus the dump and
  codegen.

## Conventions that decide *where* new code goes

- Authorization is policy code in the owning service, called through action-specific predicates.
- N+1: use the service's `sources/` dataloader, not a query in a loop.
- Cross-tree UI state, copy and dev-only surfaces: say where each lives (e.g. copy in `web-app/src/helpers/copy.ts`).
